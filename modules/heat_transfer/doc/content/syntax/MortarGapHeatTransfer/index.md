# Mortar Gap Heat Transfer Action

The mortar gap heat transfer action leverages a modular design for the computation of heat transfer.
A mortar constraint enforcing a heat flux adds contributions of well-defined physics components. The
modular contributions of phenomena such as conduction and radiation are accumulated to compute an
overall heat flux field. These contributions reside in user objects such as
[GapFluxModelConduction](GapFluxModelConduction.md) and
[GapFluxModelRadiation](GapFluxModelRadiation.md), which are called from
`ModularGapConductanceConstraint` to build residual vectors and Jacobians.

This standalone syntax remains supported. It is useful when mortar gap heat transfer is configured
independently of the `ThermalContact` syntax. For coupled thermomechanical contact,
[`ThermalContact` with `formulation = mortar`](syntax/ThermalContact/index.md) can automatically
reuse the lower-dimensional subdomains generated by an exactly matching mechanical mortar
`Contact` action when that action generates its mortar mesh.

This action can be used in two separate modes. The user may build the physics-modeling user objects
in the input and list them in the `user_created_gap_flux_models` parameter. Alternatively, the user
may add conduction or radiation, or both contributions simultaneously, with the
`gap_flux_options` parameter.

The action can be expanded with more accurate or additional physics, which, according to this design
pattern, must be implemented in `InterfaceUserObject`s.
