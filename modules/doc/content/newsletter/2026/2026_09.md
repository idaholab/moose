## MOOSE Improvements

### Complete removal of using-directives for namespace libMesh

Using-directives for namespace libMesh, i.e., `using namespace libMesh;`, have been entirely
removed. Prefer using qualified names, e.g., `libMesh::VectorValue` for `VectorValue`. If you feel
that practice becomes prohibitively verbose, cumbersome or hampers readability, leverage
using-declarations for libMesh namespace members, e.g. `using libMesh::VectorValue;`. Unity builds
will leak using-declarations across translation units within a folder, so be mindful. This is also the reason
using-directives have been removed: they leak the entire namespace across translation units.

### Changes to the MooseDocs `mergeresults` command

The MooseDocs [extensions/civet.md] `mergeresults` command now uses the current hash used to build
the documentation, rather than using the most up-to-date commit information from the remote code
repository. This allows documentation built from earlier versions of MOOSE-based code to have
consistent CI links for their version. This change was made in
[idaholab/moose#29565](https://github.com/idaholab/moose/pull/29565).

## MOOSE Modules Changes

### Contact module

Mechanical mortar contact now assembles the contact force by interpolating the nodal traction
vector with the traction basis, instead of scaling an interpolated scalar pressure by the nodal
normal of the residual row's own node. Only the former is the transpose of the weighted gap, so the
contact force is now self-equilibrated across the interface and no longer depends on secondary node
numbering. Contact forces and converged results therefore change on interfaces where the secondary
nodal normals vary along the face.

Local-basis quasistatic `mortar` and `mortar_penalty` contact Jacobians now also include
derivatives of the averaged secondary nodal normals and their tangent basis. These derivatives can
require a larger AD container on high-order or high-valence interfaces. When sliding, remeshing, or
another topology change alters the contact coupling during a solve,
`Problem/use_hash_table_matrix_assembly = true` accommodates the changing sparsity pattern
([idaholab/moose#33390](https://github.com/idaholab/moose/pull/33390)).
