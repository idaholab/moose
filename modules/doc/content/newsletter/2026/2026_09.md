## MOOSE Improvements

### Complete removal of using-directives for namespace libMesh

Using-directives for namespace libMesh, i.e., `using namespace libMesh;`, have been entirely
removed. Prefer using qualified names, e.g., `libMesh::VectorValue` for `VectorValue`. If you feel
that practice becomes prohibitively verbose, cumbersome or hampers readability, leverage
using-declarations for libMesh namespace members, e.g. `using libMesh::VectorValue;`. Unity builds
will leak using-declarations across translation units within a folder, so be mindful. This is also the reason
using-directives have been removed: they leak the entire namespace across translation units.

### Exact tie constraints with degree of freedom constraint rows

[LinearNodalConstraint.md], [EqualValueBoundaryConstraint.md] and
[EqualValueEmbeddedConstraint.md] accept a third value of `formulation`, `rows`. With it the
constraint assembles no residual and no Jacobian: it hands libMesh one degree of freedom constraint
row per secondary node, so the tie holds exactly, `penalty` may be omitted, and the constraint
reaches every matrix that is assembled rather than the system matrix alone. That last point makes
the tie effective under an `Eigenvalue` executioner, where a penalty nodal constraint reaches
neither the stiffness nor the mass matrix. `penalty` and `kinematic` are unchanged and remain the
default. [NodalConstraint.md] describes the three formulations, the parallel rules the rows obey,
and how a `Control` that changes `weights` rebuilds the rows between solves. The Solid Mechanics
module uses the same mechanism in the new
[InclinedNoDisplacementConstraint.md], which holds every node of an inclined support in the plane of
that support exactly, without the penalty parameter that
[PenaltyInclinedNoDisplacementBC.md] needs.
