## MOOSE Improvements

### Block-pair interfaces in BreakMeshByBlockGenerator

[BreakMeshByBlockGenerator.md] now always creates separate directional interface boundaries
on both sides of each cut as part of the distributed mesh support work
(see [idaholab/moose#32309](https://github.com/idaholab/moose/pull/32309)). Splitting duplicates
nodes along the selected block interfaces. To track the resulting disconnected neighbor
relationships, libMesh relies on pairs of interface boundaries, such as `blockA_blockB` and
`blockB_blockA`, with separate boundary IDs.

As a result, the parameters `split_interface`, `add_interface_on_two_sides`, and
`split_transition_interface` are deprecated. Users should remove these parameters from their
BreakMeshByBlockGenerator settings. Explicitly setting any of them to `true` produces a
deprecation warning; setting one to `false` produces an error. Interfaces are always created
on both sides and split by block pair, including interfaces between `surrounding_blocks` and
the rest of the mesh.

Previously, a single generic `interface` boundary could contain several block pairs. Unless
users checked all of them, a cohesive law applied to that boundary could also act on interfaces
they did not intend to include. This combined boundary is no longer generated. Explicit
block-pair names make the selected interfaces clear in the input file.

Users should specify the appropriate interface boundary name in the corresponding interface
kernel. For example, `blockA_blockB` identifies the interface sides on `blockA` facing `blockB`:

```text
[InterfaceKernels]
  [interface]
    type = SomeInterfaceKernel
    boundary = blockA_blockB
  []
[]
```

The parameters `interface_name`, `add_transition_interface`, and `interface_transition_name`
have also been removed. Input files referring to the former combined `interface` or
`interface_transition` boundaries should use the appropriate block-pair names instead.

## MOOSE Bug Fixes

- Apps without a Console output (e.g. `[Outputs] console = false`) no longer keep every message
  written to `_console` in memory. The buffer was never cleared and was copied at every flush, so
  long-running (sub-)apps, such as a MultiApp running many solves in one process, became slower
  and slower with the number of messages.
  ([idaholab/moose#34118](https://github.com/idaholab/moose/issues/34118))

## MOOSE Modules Changes

### Contact module

Mechanical mortar contact now assembles the contact force by interpolating the nodal traction
vector with the traction basis, instead of scaling an interpolated scalar pressure by the nodal
normal of the residual row's own node. Only the former is the transpose of the weighted gap, so the
contact force is now self-equilibrated across the interface and no longer depends on secondary node
numbering. Contact forces and converged results therefore change on interfaces where the secondary
nodal normals vary along the face.

Local-basis quasistatic `mortar` and `mortar_penalty` contact Jacobians now also include
derivatives of the averaged secondary nodal normals and their tangent basis. These derivatives can
require a larger AD container on high-order or high-valence interfaces. Because the contact
coupling changes during the solve in most contact problems, such as when surfaces slide or come into
contact, set `Problem/use_hash_table_matrix_assembly = true` to accommodate the changing sparsity
pattern
([idaholab/moose#33390](https://github.com/idaholab/moose/pull/33390)).

### Fluid properties module

The new `NASA7IdealGasFluidProperties` describes H2, O2, H2O, CH4, CO, CO2, and N2 as ideal gases
whose heat capacity, enthalpy, and entropy depend on temperature through the NASA 7-coefficient
polynomials of GRI-Mech 3.0. Its enthalpies include the enthalpy of formation, so the energy of a
mixture accounts for the heat of reaction. `IdealGasMixtureFluidProperties` accepts these gases as
components. Viscosity and thermal conductivity are not yet available for them, so they cannot yet
be used in the gas-mixture flow channels of the thermal hydraulics module
([idaholab/moose#34123](https://github.com/idaholab/moose/pull/34123)).

## libMesh-level Changes

### `2026.10.08_342ad76_0` Update

- Updated libMesh from [`90766057` to `342ad76b`](https://github.com/libMesh/libmesh/compare/90766057ef390adc9968b529e8ded2a87b0a77c7...342ad76b0c867273316a8a00f8e583810ece759e)
- Submodule moved to libMesh `master` (`342ad76b`, 2026-10-08)
- `libmesh_transform_reduce()` shim, enabling faster `std::transform_reduce()` operations on supported compilers, with fallbacks for older compilers.  Optimizations in dense vector/matrix functionals.
- Faster partitioning when using partitioners (most options other than Parmetis) whose partition quality does not improve with an initial "pre"-partitioning
- `MeshBase::n_constraint_rows()` now is an O(1) return of cached data, not a parallel-only recount
- Support for calculation of gradients on interiors of H(div) FE types
- VariationalSmoother quadrature type can now be user-overridden, enabling users to select vertex-sampling rules that are more robust for smoothing difficult meshes.
- Support for computing a "near"-dual basis on Tri6/Quad8 elements where the standard dual fails positivity requirements
- Regularized gradient of norm of a zero-vector to be zero rather than NaN.  This makes some MOOSE AD kernels more robust.
- Autotools detection, build support, and libMesh numerics support for Kokkos
- Optional support for ghosting constraint DoFs of ghosted DoFs, as needed by MOOSE Kokkos
- Improved support for shell-matrix Jacobian, sparse-matrix preconditioner `PetscNonlinearSolver` solve cases
- Allow applications to flag non-reproducible residuals to `PetscNonlinearSolver`
- More-accurate ExodusII elemental output of higher-order discontinuous variables
- Option to skip spurious interior side generation in `build_side_list_from_node_list()` on thin meshes
- New `SKEW_ANGLE` element quality metric, with implementations of that and some older metrics on more `Elem` types
- New `LOG_ONE_ENTITY_SCOPE` macro for performance logging of high-frequency events that should not be included in per-entity logging like NVTX
- Support for more IGA mesh types in `System::solve_for_unconstrained_dofs()`, for e.g. more accurate initial conditions setting on spline DoFs
- Support for `isfinite`/`isnormal`/`signbit` in MetaPHysicL
- Support for `constexpr`, Kokkos, in `MetaPhysicL::numeric_limits`
- Fixes in `HIERARCHIC` basis evaluation outside of elements, which was triggerable by FDM-based `HIERARCHIC` gradient evaluation on element boundaries
- Fix for `HIERARCHIC` shape function orientation consistency on some 3D meshes
- Fix for corner cases in `Poly2TriTriangulator` refinement code, used by `XYDelaunay` and other MOOSE mesh generators
- Fix for neighbor-finding on polyhedral meshes
- Fixes and test coverage for more reference-space node position queries on `Tri7` and other high-geometric-order elements
- Automatic calculation of topological data on higher-order geometric elements
- Refactoring+optimization+robustness improvements in `DistributedMesh` copy constructor
- Non-ASCII output fix in `MeshBase::get_info()`, and more robustness on unprepared meshes
- Added more stringent mesh preparation assertions, made test cases compatible with them
- Fix for corner case where a post-redistribution distributed mesh might have ghosted-element neighbors that still have `remote_elem` neighbor links to each other
- Fix for OpenMP libMesh thread backend sometimes using a full thread count when asked to temporarily use a reduced count
- Fix for excessive-peak-memory-usage bug in pthreads parallel_reduce() backend
- Fix for vector variable output in `Nemesis_IO`
- Fix in reduced_basis training
- Fix for `BoundaryInfo::sync` to an unprepared `DistributedMesh` with `METHOD=dbg`
- C++20 compiler compatibility fixes in MetaPhysicL
- Better error message when trying to read a checkpoint split mesh with a bad split count
- Avoid dropping error messages from non-rank-0 failures on parallel unit test suite runs
- Added `AGENTS.md` and libMesh-Civet-CI-failures skill files for AI agents
- Apply `--enable-werror` flag to C/C++ preprocessing only, not linking, to avoid triggering errors from warnings in third-party code triggered by compilers using Link-Time Optimization

## PETSc-level Changes

The PETSc submodule was updated from
[3.25.4 to 3.26.0](https://gitlab.com/petsc/petsc/-/compare/v3.25.4...v3.26.0).
OpenBLAS is held at 0.3.33 rather than the 0.3.34 that PETSc 3.26.0 downloads by default,
because 0.3.34 hangs in threaded direct solves (MUMPS, SuperLU_DIST and STRUMPACK) when
`OMP_NUM_THREADS` is greater than one.
