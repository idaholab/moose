## MOOSE Improvements

### NEML2 v3 Integration

The MOOSE–NEML2 integration has been updated to support NEML2 v3, described in the
recent SoftwareX paper
[*Version 3—NEML2: An efficient and modular multiphysics constitutive modeling library
for hybrid computing environments*](https://doi.org/10.1016/j.softx.2026.102937).

NEML2 v3 enables Python-based constitutive model development, while the updated MOOSE
interface supports two C++ execution modes: `cpp-aoti` for ahead-of-time compiled,
Python-free model evaluation and `cpp-eager` for direct, compile-free evaluation through
an embedded Python interpreter. The integration also introduces MPI-aware CPU and GPU
device scheduling for compiled models, improves model data and derivative handling and
failure diagnostics, and simplifies NEML2 and PyTorch dependency configuration through
the active Python environment. ([idaholab/moose#34170](https://github.com/idaholab/moose/pull/34170))

## libMesh-level Changes

### `2026.10.21_69c4f84_0` Update

- Updated libMesh from [`342ad76b` to `69c4f84e`](https://github.com/libMesh/libmesh/compare/342ad76b0c867273316a8a00f8e583810ece759e...69c4f84efcaa169b0bf022cff32fc9cdaa4af79b)
- Support in ExodusII_IO for subdomains with multiple element types, by automatically using an additional block for each "extra" element type.  The good news: users should no longer need to manually generate extra subdomains when discretizing a domain with multiple element types.  The bad news: nearly every place in MOOSE code and input file syntax and documentation where we use "block" to mean "subdomain" is now wrong in a much-less-hypothetical way.
- `VTK_POLYHEDRON` read support
- Added a new `L2_LAGRANGE_GLL` `FEFamily`, using the Lagrange property at Gauss-Lobatto quadrature point locations to enable diagonal mass matrix construction when using `QGaussLobatto` quadrature.
- Added a robust near-dual basis for `Tri7` elements
- Adjusted `DofObject` data structures to support higher numbers of components-per-variable on a single object.  This fixes incompatibilities with higher-order `FE` types, including discontinuous `Q^p` elements with `p` as low as 6 on hexahedra.
- Support for saving disjoint-neighbor pairs in CheckpointIO files
- Support for `QuadShell4` elements in `MeshModification::all_tri()`
- Fixes and test coverage for heterogeneous constraint equation support in `PetscNonlinearSolver`
- Fixes for `nodal_soln` evaluation on `Prism20`, `Prism21`, and `Pyramid18`
- Changes to `QGRID` rule to fix even-lower-than-optimal convergence on Tri/Tet/Prism/Pyramid elements
- Bug fix for `calculator` projection calculations on Flex IGA meshes (or any other systems using an external constraint matrix)
- Compatibility fixes for `calculator` app with newer GCC
- Better and more flexible printed output from `calculator` app
- New FEMSystem example using MetaPhysicL automatic differentiation for Jacobian calculations
- New cell-centered-Finite-Volume example using polygonal mesh support
- MetaPhysicL updates:
  - `constexpr` and other improvements to `numeric_limits` on MetaPhysicL classes to enable more GPGPU use with Kokkos
  - GPGPU support for `NumberArray` in Kokkos device code
- Added shell `Elem` support to Szabo-Babuska (`SZABAB`) finite element family
- Fix to avoid configure autodetection of VTK libraries built with incompatible MPI implementations
