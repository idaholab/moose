# Contact Action

!syntax description /Contact/ContactAction

## Description

ContactAction is a MOOSE action that constructs objects needed for mechanical contact enforcement. This
is invoked by including the [Contact](syntax/Contact/index.md) block at the top level in a MOOSE input file.
See the page documenting the syntax for that block for a description, example usage, and parameters.

For the `mortar` and `mortar_penalty` formulations, ContactAction forwards
[!param](/Contact/ContactAction/mortar_3d_qp_mapping) to its generated mortar constraints and user
objects. See [AutomaticMortarGeneration.md#quadrature-point-mapping] for the two mapping methods.
The parameter has no effect in 2D, and every mortar consumer on the same primary-secondary boundary
pair must use the same mapping mode.

For the `mortar` formulation, [!param](/Contact/ContactAction/use_nodal_scaling) is forwarded to the
generated Lagrange-multiplier user object to improve the conditioning of partially covered
(secondary edge dropping) interfaces; it requires
[!param](/Contact/ContactAction/correct_edge_dropping) and is described in
[ComputeWeightedGapLMMechanicalContact.md#node-based-scaling-for-edge-dropping].

For the `mortar` formulation, [!param](/Contact/ContactAction/c_strategy) chooses how the contact
constants are set. With the default `user` strategy, [!param](/Contact/ContactAction/c_normal) and
[!param](/Contact/ContactAction/c_tangential) are used as given. With the `physical` strategy, the
action derives a contact stiffness $D_j$ at each secondary node $j$ from the elasticity tensors of
the two contacting bodies:

!equation
D_j = \left( \frac{h_s}{C_{nn,s}} + \frac{h_p}{C_{nn,p}} \right)^{-1},
\qquad C_{nn} = n_a n_b n_c n_d C_{abcd},

where $C_{nn}$ is the normal acoustic stiffness of a body for the contact normal $\mathbf{n}$, and
$h$ is the depth normal to the contact face of the element adjacent to the face, computed as the
element volume divided by the face measure. $D_j$ is the stiffness of the two element layers in
series, averaged over the mortar segments with the mortar test function. It is used as both the
normal and tangential contact constant, since the shear and normal stiffness of an isotropic body
are of the same order, with [!param](/Contact/ContactAction/normalize_c) implied.

The contact multipliers are also represented as $D_j$ times their stored values, and the multiplier
rows are rescaled from pressure to force units. These two changes put the multiplier rows and columns
of the Jacobian at the order of the elasticity block, so the user does not choose the multiplier
scaling. Each node's $D_j$ is fixed the first time the node has mortar coverage, which keeps the
meaning of the stored multiplier values unchanged as the contact surfaces move. The physical
strategy cannot be combined with user-set contact constants or multiplier scaling, with automatic
scaling, or with [!param](/Contact/ContactAction/mortar_dynamics). For Coulomb friction it requires
`friction_projection_degree = ONE`: the degree-two residual is homogeneous of degree two in the
pressures, so its Jacobian scales with the solution-dependent contact pressure and no fixed scaling
brings it to the order of the elasticity block. Use
[!param](/Contact/ContactAction/secondary_elasticity_tensor_base_name),
[!param](/Contact/ContactAction/primary_elasticity_tensor_base_name), and
[!param](/Contact/ContactAction/elasticity_tensor_is_ad) to identify the elasticity tensor
properties.

For the mortar Lagrange-multiplier contact formulation, [!param](/Contact/ContactAction/lm_space)
controls the finite element space used for mortar Lagrange multiplier variables generated by
ContactAction. The `MATCH_DISPLACEMENT` option gives these generated mortar variables the same order
as the displacement variables. The `LINEAR` option creates first-order LAGRANGE generated mortar
variables even when the displacement variables are higher order. This option only affects variables
created by ContactAction; users who define mortar constraints manually still choose the Lagrange
multiplier family and order directly in `[Variables]`.

Lower-order contact multiplier interpolations are a standard option for mortar contact with
quadratic surface discretizations. Puso, Laursen, and Solberg discuss alternative multiplier
interpolations for quadratic-element mortar contact and show that corner-node/linear contact
pressure fields can avoid inconsistencies that arise with quadratic contact pressure interpolations
while retaining good convergence [!cite](puso2008segment).

For node-to-segment mechanical contact, the action offers the possibility to automatically set up
mechanical contact pairs given a maximum distance between contacting boundary centroids.
To use that option, the user must set `automatic_pairing_method = CENTROID`.
The user can leverage this capability by providing `automatic_pairing_distance` and
`automatic_pairing_boundaries`. This is particularly useful when many feasible contact
interactions can take place in a periodically repeating pattern.

Alternatively, also for
node-to-segment, the user can choose to select a computation of proximity based on nodal
locations. In essence, for all boundaries provided by the user in `automatic_pairing_boundaries`,
the action will search for all nodes whose distance is less than `automatic_pairing_distance`.
If so, each nodal pair distance from different boundaries less than the `automatic_pairing_distance`
distance will create a contact pair. Repeated contact pairs are automatically eliminated. In order to
activate this feature, in addition to `automatic_pairing_boundaries` and `automatic_pairing_distance`, the
user needs to set the input parameter `automatic_pairing_method = NODE`.

For either method, the boundary with the larger area in each automatically generated pair is
assigned as the primary surface. See
[AutomaticContactPairingGenerator](/AutomaticContactPairingGenerator.md) for details of the pairing
and primary/secondary assignment.

Automatic pairing requires the mesh to be built by mesh generators, because the action appends an
[AutomaticContactPairingGenerator](/AutomaticContactPairingGenerator.md) to the mesh generator tree.
To read a mesh file, use a [FileMeshGenerator](/FileMeshGenerator.md) in the `[Mesh]` block.
